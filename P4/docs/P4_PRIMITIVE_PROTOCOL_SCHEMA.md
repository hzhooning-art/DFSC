# Primitive Protocol Registry Schema

The registry uses schema `DFSC-Primitive-Protocol-v1`. Every backend receives
the same six evidence dimensions:

| field | meaning |
|---|---|
| `value` | finite and reference-checked function values |
| `gradient` | finite and directionally checked parameter gradients |
| `calibration` | noisy inverse recovery with a declared baseline |
| `module_reuse` | composition into a trainable SciML module |
| `ood` | evaluation outside the calibration domain |
| `long_horizon` | error/stability at extended propagation time |

Each field is one of:

- `pass`: directly measured in the normalized record;
- `reported_prior_validation`: measured in an earlier protocol report but not
  yet converted to the common schema;
- `warning`: measured with an explicit limitation;
- `missing`: not measured;
- `fail`: measured and failed.

The registry never converts `missing` to `pass`. Its `coverage` value is a
coverage indicator, not a scientific quality score. Backend metrics must not be
pooled when their reference problems or domains differ.

The current registry is generated by
`P4/experiments/p4_protocol_registry.py` and written to
`P4/results/p4_primitive_protocol_registry.json`.

Runtime profiling uses schema `DFSC-Primitive-Profile-v1` and records the
device-synchronized mean latency, samples per second, output shape, finite
output status, and peak GPU allocation for each backend and batch size. It is
generated by `P4/experiments/p4_primitive_profile.py`.

The backend-independent interface smoke test is wired to
`.github/workflows/p4-protocol-smoke.yml`; it runs on CPU and does not treat GPU
availability as a correctness requirement.

The common module-level OOD task uses schema `DFSC-Common-Module-OOD-v1`:
each backend receives short noisy observations, predicts its explicit physical
parameters, and propagates to a shared target time. The result reports the
primitive-composed model and a pure MLP under the same data and training
budget. It is an applicability test, not a universal ranking; a backend may
lose to the baseline, as the matrix-exponential result currently does.
The current task is repeated at observation noise `sigma=0.003` and
`sigma=0.01`, and target times `t=1.0` and `t=1.5`; both noise and horizon are
retained as explicit registry dimensions.
